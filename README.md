# EngageX — GENAI-12 Community Challenge Engine

EngageX — это ИИ-модератор для онлайн-сообществ (Telegram, Discord и др.), который сам:
- проектирует и генерирует ежедневные «вызовы» (challenges),
- доставляет их участникам через бота,
- собирает метрики вовлечённости / удержания / продаж,
- и автоматически подстраивает стратегию под поведение сообщества.

Репозиторий реализует задачу **GENAI-12**: четырёхнедельный цикл вызовов с фокусом на
вовлечение, удержание, конверсию и реактивацию.

---

## 1. Основные возможности

- 🔁 **4-недельный цикл целей**
  - Неделя 1 — Вовлечение (больше сообщений и обсуждений)
  - Неделя 2 — Удержание (формирование привычки участвовать)
  - Неделя 3 — Продажи / конверсия (мягкие целевые действия)
  - Неделя 4 — Реактивация неактивных участников

- 🧠 **Генерация персонализированных вызовов (LLM)**
  - 3–5 вызовов в день под текущую цель недели
  - адаптация под тематику комьюнити (SaaS / фитнес / образование / крипто)
  - связь с продуктом (новые фичи, шаблоны, кейсы использования)

- 🤖 **Телеграм-бот / модератор**
  - публикует вызовы в канале / чате
  - отправляет напоминания неактивным участникам
  - поддерживает кнопку «Узнать больше»:
    - объяснение цели вызова
    - примеры ответов
    - возможность задать уточняющий вопрос ИИ

- 📊 **Аналитика и обучение на метриках**
  - % участников, выполнивших вызов
  - рост числа сообщений и активных пользователей
  - конверсия в целевые действия (регистрация, покупка, возврат в чат)
  - сравнение эффективности разных формулировок
  - авто-адаптация: система усиливает наиболее результативные паттерны

## 2. Структура проекта

Директории по корню репозитория:

- `bot/` — Telegram-бот и сценарии взаимодействия пользователей с вызовами  
- `parser/` — сбор и очистка данных из сообществ (посты, ответы и т.п.)  
- `services/` — backend-сервисы и модельный сервер (LLM, генерация, скоринг)  
- `analytics/` — анализ метрик, отчёты, эксперименты  
- `dashboard/` — панель администратора / дэшборд (Streamlit или веб-UI)  
- `automatika/` — расписания, планировщики, автозапуск ежедневных задач  
- `train/` — обучение и дообучение моделей, подготовка датасетов  
- `models/` — локальные модели и чекпоинты  
- `data/` — синтетические сообщества, истории публикаций, временные данные  
- `logs/` — логи работы сервисов  
- `alembic/`, `alembic.ini` — миграции БД (PostgreSQL)  
- `docker-compose.yml` — инфраструктура через Docker (БД + сервисы)  
- `requirements.txt` — Python-зависимости  
- `env.example` — пример настроек окружения  
- `.env` — ваши реальные настройки (в git не коммитится)

## 4. Установка и зависимости

### 4.1. Клонировать репозиторий

```bash
git clone https://github.com/RusBarTeam/EngageX.git
```

### 4.2. Создать и активировать виртуальное окружение
````
python -m venv .venv
````
macOS / Linux
````
source .venv/bin/activate
````
Windows (PowerShell)
````
.venv\Scripts\Activate.ps1
````

4.3. Установить зависимости
````
pip install --upgrade pip
pip install -r requirements.txt
````

## 5. Настройка окружения
### 5.1. Создать .env из примера
````
cp env.example .env
````
### 5.2. Заполнить ключевые параметры

Открой .env и пропиши значения (точный список смотри в env.example, ниже — типичный набор):
````
# Режим
APP_ENV=dev

# База данных
DB_HOST=localhost
DB_PORT=5432
DB_NAME=engagex
DB_USER=engagex
DB_PASSWORD=change_me

# Telegram
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here

# LLM / модели
LLM_MODEL_PATH=/absolute/path/to/local/model
LLM_MAX_TOKENS=1024

# Прочее
LOG_LEVEL=INFO
````

## 6. База данных и миграции
### 6.1. Поднять PostgreSQL (вариант через Docker)

В docker-compose.yml обычно описан сервис БД. Запускаем:
````
docker compose up -d db
````

Если сервис называется по-другому (например postgres), используй его имя.

### 6.2. Применить миграции Alembic
````
alembic upgrade head
# при необходимости:
# alembic -c alembic.ini upgrade head
````


После этого структура таблиц для участников, постов, вызовов и метрик будет создана.

## 7. Запуск проекта

Ниже — базовый сценарий запуска основных компонентов.
Названия файлов-входных точек ориентировочные: если у тебя они отличаются, просто подставь свои.

### 7.1. Модельный сервер / backend-сервисы

Сервис, который отвечает за генерацию и оценку вызовов:

# вариант 1: прямой запуск
````
python services/model_server.py
````
или, если используется uvicorn внутри:
````
# python -m services.model_server
````

После запуска API будет доступно на порту, указанном в model_server.py или .env
(например http://localhost:8000).

### 7.2. Планировщик / автоматическая генерация вызовов

Периодический запуск пайплайна (сбор данных → анализ → генерация недельных/дневных вызовов):

# единичный прогон полного пайплайна
````
python run_pipeline.py
````



7.3. Telegram-бот

Бот, который публикует вызовы, шлёт напоминания и обрабатывает кнопку «Узнать больше»:

````
python -m bot.main
````

### 7.4. Админ-дашборд / панель управления

Для просмотра метрик и ручного управления кампаниями:

пример для Streamlit
````
streamlit run dashboard/app.py
````
# или другое имя файла в папке dashboard/


После запуска панель будет доступна в браузере (обычно http://localhost:8501).

## 8. Запуск всего стека через Docker (опционально)

Если в docker-compose.yml уже описаны сервисы (БД, модельный сервер, бот, дэшборд), можно поднять всё одной командой:

````
docker compose up --build
````

Это:
поднимет PostgreSQL,
запустит backend / model server,
запустит бота,
(опционально) поднимет dashboard.

Остановить всё:
````
docker compose down
````

````
pip install -r requirements.txt

````

Запустить модельный сервер, планировщик и бота (как в разделе 7).

## 10. Статус и ограничения

Текущий фокус — одно сообщество и одна тематика (по условиям GENAI-12).

Вызовы генерируются и оптимизируются на основе синтетических данных
и истории взаимодействий внутри этого сообщества.

Добавление поддержки нескольких сообществ и полноценного multi-tenant режима — отдельный этап развития.
